# MtG Analyzer — 役割で考えるデッキ構築

`index.html` をブラウザ（Chrome / Edge）で開くだけで動きます。ビルドもサーバーも要りません。

## できること
- **MTGO形式の入出力**
  - インポート: `.txt`（`4 Lightning Bolt` 形式、空行または `Sideboard` 行より下がサイド）／`.dek`（MTGOのXML）。ファイル選択・貼り付け・ドラッグ&ドロップに対応
  - エクスポート: `.txt`／`.dek`（取得できたカードには MTGO の CatID を入れます）／クリップボードにコピー
  - 分割カードは MTGO 表記 `Fire/Ice` と Scryfall 表記 `Fire // Ice` を自動で変換
- **カード検索**: 英語名の入力補完、日本語名の検索、Scryfall の検索構文（例: `t:creature c:r mv<=2`）
- **役割の自動分類**: 土地／マナ加速／ドロー/アド／単体除去／全体除去／打ち消し／サーチ／墓地回収／保護／脅威/勝ち筋。役割チップをクリックすると手動で変更できます（金の縁＝手動設定）
- **変身する両面カード**: 変身・合体・反転のカードは、手札から唱えられない裏面の役割を「変身後:〇〇」（点線のチップ）として別に表示し、役割の枚数・大カテゴリ・妨害の内訳・一人回しには数えません。モードを持つ両面・出来事・分割カードは両方の面を数えます
- **分析**: 役割の比率と目安の範囲、マナカーブ、色シンボルと色源の比較、推奨土地枚数（Frank Karstenの式がベース）、アドバイス
- **一人回し（メインの動き）**: 相手が何もしない前提でデッキを2,000回シャッフルし、6ターン目まで土地を置いて呪文を唱える（マリガンなし・7枚キープ）。主力カード（デッキ画面の☆で指定。未指定なら【勝ち手段】【コンボ/展開】）を何ターン目までに唱えられたか、何もできなかったターン、マナの使い残し、妨害を構えられた率を先手・後手別に表示。2マナ土地、Tron（Planar Nexus込み）、神座、タップイン、バウンスランド、フェッチ、土地サーチ、占術・キャントリップ、マナを出すクリーチャー・アーティファクト、運命を貪るものの初手公開に対応。サーチ・加速・占術のカードを1種類ずつ抜いたときの差も出します（`js/manasim.js`）
- **アドバイス**: 前提チェック（枚数・土地・色）／メインの動き（一人回しの主力の登場率・妨害を手札に持っていた率と構えられた率）／環境への対策 に分けて表示。上位デッキや目安との構成の違い（多め・少なめ）は、メタ外のカードを試す妨げにならないよう注意ではなく折りたたみの参考情報として出します
- **保存**: 作業中のデッキは自動保存。名前を付けて複数のデッキを保存できます（ブラウザの localStorage）

## Scryfall API の使い方（上限対策）
- すべてのリクエストを1本のキューに並べ、**最低120ms間隔**（約8回/秒）で送信します。Scryfallの推奨は1回あたり50〜100msです
- デッキの読み込みは `/cards/collection` で **75枚ずつまとめて**取得します（60枚デッキなら1回、100枚なら2回）
- 取得したカードは **24時間キャッシュ**し、同じカードは再取得しません
- 入力補完は入力が止まってから350ms後にだけ送信します
- 429（リクエスト過多）が返ってきたら、`Retry-After` または指数バックオフで待ってから再試行します
- 画面下に送信回数とキャッシュの利用回数を表示しています

## 上位デッキとの比較（ベンチマーク）
分析パネルの「上位デッキとの比較」でフォーマットを選ぶと、MTGO で勝っているデッキ（Challenge 上位・リーグ 5-0）の役割の枚数と比べられます。デッキのアーキタイプは自動で判定されます。手動で選ぶこともできます。

- 集計は GitHub Actions（`.github/workflows/benchmarks.yml`）が **毎週月曜 4:23（日本時間）** に実行し、結果を `benchmarks/` にコミットします
- Actions タブの「Build benchmarks」→「Run workflow」で手動実行もできます（集計期間の日数を指定可）
- Actions がリポジトリにコミットするので、**ローカルで作業する前に `git pull`** してください
- 集計スクリプトは `scripts/build-benchmarks.mjs`。役割判定はアプリと同じ `js/roles.js` を使うので、ルールを直すと次回の集計にも反映されます
- `benchmarks/diagnostics/<format>.json` に役割判定の見直し候補（「その他」としか判定されない採用率の高いカード、役割が多すぎるカード、パワー1以下なのに脅威扱いのクリーチャーなど）を出力します

| 種類 | 出典 | ライセンス |
|---|---|---|
| デッキリスト | MTGO 公開デッキリスト（[fbettega/MTG_decklistcache](https://github.com/fbettega/MTG_decklistcache) 経由） | GPL-3.0。集計値のみ公開し、生のデッキリストは再配布しません |
| アーキタイプ定義 | [Badaro/MTGOFormatData](https://github.com/Badaro/MTGOFormatData) | MIT（`benchmarks/archetypes/` に定義を同梱） |
| カードテキスト | [Scryfall](https://scryfall.com) のバルクデータ（oracle-cards） | Scryfall API 利用規約 |

## GitHub Pages で公開する
1. GitHub で **public** の空リポジトリを作成（README などは追加しない）
2. このフォルダで `git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git` → `git push -u origin main`
3. リポジトリの Settings → Pages → Source を「Deploy from a branch」、Branch を `main` / `/ (root)` にして Save
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けます

以後は `main` に push するたびに自動で更新されます。`.nojekyll` は Jekyll の変換を止めるためのファイルなので消さないでください。
デッキの保存先はブラウザ（端末ごと）なので、PC とスマホの間ではエクスポート／インポートで受け渡してください。

## ファイル構成
```
index.html
css/style.css
js/scryfall.js  … APIクライアント（キュー・キャッシュ・まとめて取得）
js/deckio.js    … MTGO .txt / .dek の読み込みと書き出し
js/cardmodel.js … Scryfallのカードを最小限の形に変換（アプリと集計で共通）
js/roles.js     … 役割の判定ルール・フォーマット別の目安・分析（アプリと集計で共通）
js/archetype.js … アーキタイプ判定（アプリと集計で共通）
js/app.js       … 画面とその操作
scripts/build-benchmarks.mjs … 上位デッキの集計（GitHub Actionsで実行）
benchmarks/     … 集計結果（Actionsが自動更新）
```
役割の判定ルールは `js/roles.js` の `RULES`（オラクルテキストの正規表現）を、目安の枚数は `targets()` を編集すると変えられます。
