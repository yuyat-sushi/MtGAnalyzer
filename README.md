# MtG Analyzer — 役割で考えるデッキ構築

`index.html` をブラウザ（Chrome / Edge）で開くだけで動きます。ビルドもサーバーも要りません。

## できること
- **MTGO形式の入出力**
  - インポート: `.txt`（`4 Lightning Bolt` 形式、空行または `Sideboard` 行より下がサイド）／`.dek`（MTGOのXML）。ファイル選択・貼り付け・ドラッグ&ドロップに対応
  - エクスポート: `.txt`／`.dek`（取得できたカードには MTGO の CatID を入れます）／クリップボードにコピー
  - 分割カードは MTGO 表記 `Fire/Ice` と Scryfall 表記 `Fire // Ice` を自動で変換
- **カード検索**: 英語名の入力補完、日本語名の検索、Scryfall の検索構文（例: `t:creature c:r mv<=2`）
- **役割の自動分類**: 土地／マナ加速／ドロー/アド／単体除去／全体除去／打ち消し／サーチ／墓地回収／保護／脅威/勝ち筋。役割チップをクリックすると手動で変更できます（金の縁＝手動設定）
- **分析**: 役割の比率と目安の範囲、マナカーブ、色シンボルと色源の比較、推奨土地枚数（Frank Karstenの式がベース）、アドバイス
- **保存**: 作業中のデッキは自動保存。名前を付けて複数のデッキを保存できます（ブラウザの localStorage）

## Scryfall API の使い方（上限対策）
- すべてのリクエストを1本のキューに並べ、**最低120ms間隔**（約8回/秒）で送信します。Scryfallの推奨は1回あたり50〜100msです
- デッキの読み込みは `/cards/collection` で **75枚ずつまとめて**取得します（60枚デッキなら1回、100枚なら2回）
- 取得したカードは **24時間キャッシュ**し、同じカードは再取得しません
- 入力補完は入力が止まってから350ms後にだけ送信します
- 429（リクエスト過多）が返ってきたら、`Retry-After` または指数バックオフで待ってから再試行します
- 画面下に送信回数とキャッシュの利用回数を表示しています

## GitHub Pages で公開する
1. GitHub で **public** の空リポジトリを作成（README などは追加しない）
2. このフォルダで `git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git` → `git push -u origin main`
3. リポジトリの Settings → Pages → Source を「Deploy from a branch」、Branch を `main` / `/ (root)` にして Save
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けます

以後は `main` に push するたびに自動で更新されます。`.nojekyll` は Jekyll の変換を止めるためのファイルなので消さないでください。
デッキの保存先はブラウザ（端末ごと）なので、PC とスマホの間ではエクスポート／インポートで受け渡してください。

## ファイル構成
```
index.html
css/style.css
js/scryfall.js  … APIクライアント（キュー・キャッシュ・まとめて取得）
js/deckio.js    … MTGO .txt / .dek の読み込みと書き出し
js/roles.js     … 役割の判定ルール・フォーマット別の目安・分析
js/app.js       … 画面とその操作
```
役割の判定ルールは `js/roles.js` の `RULES`（オラクルテキストの正規表現）を、目安の枚数は `targets()` を編集すると変えられます。
